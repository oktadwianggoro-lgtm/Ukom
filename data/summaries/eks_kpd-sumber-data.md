# KPD sebagai Sumber Data Ekstensifikasi (SE-11/PJ/2020)

*(Lihat juga ringkasan lengkap KPD di kompetensi Profiling Wajib Pajak — `prf_kpdl-tujuan-jenis.md` dan `prf_tahapan-probis-kpd.md`. Ringkasan ini fokus pada peran KPD sebagai pemasok data ke proses Ekstensifikasi.)*

## Alur KPD → SP2DK Ekstensifikasi
1. Data dari **KPDL Berbasis Kewilayahan**, **KPDL Penugasan Lapangan Lainnya**, **KPDL Non Tusi**, atau **Pihak Eksternal (PKS)** direkam pada **Aplikasi Coretax**.
2. **Validasi Material** (oleh Atasan Langsung): cek kelengkapan field (NIK/NPWP valid, KPP tujuan benar, alamat jelas), relevansi klasifikasi **ICALEP** (Income, Cost, Asset, Liability, Equity, Profile), akurasi nilai.
3. **Validasi Formal** (oleh **Kasi PKD**): kelengkapan & validitas data (NIK via Appportal), standardisasi penulisan nama/alamat, data belum ada di basis DJP, Masa/Tahun Pajak belum daluarsa.
4. Data menjadi **DSE** (Data Sumber Ekstensifikasi, untuk WP belum ber-NPWP) atau **Data Penguji** (untuk WP ber-NPWP) di **Modul Ekstensifikasi SIDJP Nine / Approweb**.
5. **Kasi PKD** mendistribusikan ke **Kasi Pengawasan II–VI** → penugasan ke **AR** → penerbitan **SP2DK** (hari berikutnya) → disampaikan **Langsung** atau **Pos/Kurir**.
6. **Respon WP** terhadap SP2DK dari KPD: (1) WP mendaftarkan diri; (2) WP tidak memberi tanggapan; (3) WP menolak mendaftar/menyatakan tidak dapat didaftarkan; (4) WP tidak ditemui/WP Kempos.
7. Berujung pada **LHP2DK** dengan opsi: pemberian NPWP/NITKU **secara jabatan**; P2DK **tidak ditindaklanjuti** (6 kondisi — sama seperti kompetensi Profiling); Pengawasan lanjutan (penyampaian/pembetulan SPT); pengusulan Pemeriksaan/Bukper; atau tidak ada tindak lanjut.

## Catatan
- KPD adalah **sumber data hulu** bagi proses Ekstensifikasi (mengisi DSE) maupun bagi Pengawasan Intensifikasi (mengisi Data Penguji) — soal sering menguji perbedaan muara data KPD berdasarkan status ber-NPWP/belum ber-NPWP WP yang didata.
